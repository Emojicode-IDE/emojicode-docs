# Emojicode言語のバグ

Emojicode の公式コンパイラ（[`master`](https://github.com/emojicode/emojicode/tree/master)、コミット [`4dec45b`](https://github.com/emojicode/emojicode/commit/4dec45b497e4f4dce7f5f5ae11a00d8e8e9af67c)）で見つかっているバグのうち、まだ修正されていないものです。この IDE のコンパイラも同じ動きをします。

この IDE で修正パッチが当たっているものは [修正済みのバグ](patched.md) にあります。

## 実数を文字列にすると、四捨五入されずに切り捨てられる

`🔡 実数 桁数❗️` は、指定した桁より下を切り捨てます。さらに、実数の誤差のせいで、思ったより 1 小さい値になることがあります。

```emojicode
🏁 🍇
  😀 🔡 3.05 2❗️❗️
  😀 🔡 3.14159❗️❗️
🍉
```

```output
3.04
3.141589
```

正しくは `3.05`、`3.141590` です。桁数を省いた `🔡 実数❗️` は小数点以下 6 桁なので、同じことが起きます。

```keywords
実数
小数
丸め
四捨五入
切り捨て
誤差
```

## `📦 files` の `📤` `📥` `📯` が使えない

`files` パッケージのソース（`files.🍇`）には、標準出力・標準入力・標準エラーを表す `📤` `📥` `📯` が書かれていますが、コメントになっていて宣言されておらず、C++ 側の中身もありません。使うと `has no suitable 📤` のようなコンパイルエラーになります。

```keywords
files
stdout
stdin
stderr
has no suitable
```

## 新しめの絵文字を名前に使えない

コンパイラが知っている絵文字の一覧が古いため、`🟢` `🟡` のような比較的新しい絵文字は、型やメソッドの名前に使えません。`Expected Identifier` というコンパイルエラーになります。

```emojicode error
🔘 🚦 🍇
  🆕▶️🔴
  🆕▶️🟢
🍉

🏁 🍇
  🆕🚦▶️🔴❗️ ➡️ light
🍉
```

```text
Expected Identifier
```

```keywords
絵文字
識別子
名前
Expected Identifier
Unicode
```

## 引数の型が同じメソッドを 2 つ書いても、エラーにならない

同じ名前で、引数の型もまったく同じメソッドを 2 つ書いても、コンパイルエラーになりません。呼ぶと、後に書いたほうが黙って使われます。戻り値の型だけが違う 2 つでも同じです（[クラス](../types/classes.md)）。

```emojicode
🐇 🖨 🍇
  🆕 🍇🍉

  ❗️ 📢 n 🔢 🍇
    😀 🔤1 つ目🔤❗️
  🍉

  ❗️ 📢 n 🔢 🍇
    😀 🔤2 つ目🔤❗️
  🍉
🍉

🏁 🍇
  📢 🆕🖨❗️ 5❗️
🍉
```

```output
2 つ目
```

コンパイラには、宣言が重なっていないかを調べる関数（`FunctionResolver::duplicateDeclarationCheck`）がありますが、どこからも呼ばれていません。

```keywords
オーバーロード
overload
重複した宣言
同じシグネチャ
duplicate declaration
```

## `🌱` の `🚯` が、元のリストから要素を消さない

`🌱`（リストのイテレーター）の `🚯` は、標準ライブラリのドキュメントコメントでは「最後に取り出した要素をリストから取り除く」メソッドですが、元のリストは変わりません。リスト（`🍨`）は値型なので、`🌱` は作るときにリストのコピーを持ち、`🚯` はそのコピーから消すためです（[リストと辞書](../basics/collections.md)）。

```emojicode
🏁 🍇
  🍿 1 2 3 🍆 ➡️ list
  🆕🌱🐚🔢🍆 list❗️ ➡️ it
  🔽 it❗️
  🚯 it❗️
  😀 🔡 📏 list❓❗️❗️
🍉
```

```output
3
```

要素を除いたリストがほしいときは、`🐭` を使います。`🐭` は条件に合う要素だけを残すので、除きたい要素で 👎 を返す条件を渡します。

```keywords
イテレーター
iterator
要素を消す
remove
erase
```

## `📦 files` の `📓` で、残りより多く読もうとすると、読めた分も返らない

`files` パッケージの `📓`（決まったバイト数を読む）で、ファイルの残りより多いバイト数を求めると、途中まで読めた分も返さずにエラーを投げます。その後は、`🔛` で位置を戻しても、読み込みがすべてエラーになります（[パッケージとドキュメントコメント](../advanced/packages.md)）。

```emojicode
📦 files 🏠

🏁 🍇
  🍺 📻🐇📄 🔤a.txt🔤 📇 🔤abc🔤❗️❗️
  🍺 🆕📄▶️📜 🔤a.txt🔤❗️ ➡️ file
  🆗 data 📓 file 5❗️ 🍇
    😀 🍺 🔡 data❗️❗️
  🍉
  🙅 error 🍇
    😀 🔤5 バイトは読めない🔤❗️
  🍉
  🔛 file 0❗️
  🆗 data 📓 file 1❗️ 🍇
    😀 🍺 🔡 data❗️❗️
  🍉
  🙅 error 🍇
    😀 🔤戻しても読めない🔤❗️
  🍉
🍉
```

```output
5 バイトは読めない
戻しても読めない
```

中身の C++ の関数は、読んだあとにファイルのストリームが失敗の状態になっていればエラーを投げます。残りより多く読もうとすると失敗の状態になり、その状態は元に戻されないので、後の読み込みもすべて失敗します。また、エラーのメッセージ（`💬`）は、そのとき残っているエラーの番号（C の `errno`）から作られるので、`Not a tty` のような、読み込みとは関係のない文になります。

読む量がわからないときは、`📏🕊📑` で先に大きさを調べるか、`📇🐇📄` でファイル全体を読みます。

```keywords
files
ファイル
読み込み
fread
EOF
errno
```
