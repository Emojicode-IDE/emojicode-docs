# Emojicode言語のバグ

Emojicode の公式コンパイラ（[`master`](https://github.com/emojicode/emojicode/tree/master)、コミット [`4dec45b`](https://github.com/emojicode/emojicode/commit/4dec45b497e4f4dce7f5f5ae11a00d8e8e9af67c)）で見つかっているバグです。この IDE のコンパイラは公式コンパイラと同じ動きをするので、ここにあるバグはこの IDE でも起きます。

ただし、公式コンパイラが落ちたり、終わらなくなったりするところでは、この IDE は `[EJ001]` のような ID をつけたエラーで止まります。IDE の出力に出た ID を押すと、ここのその項目が開きます。

::: cards

## `🔫` に空の文字列を渡すと、終わらない {#EJ001}

`🔫`（文字列を区切る）に空の文字列を渡すと、公式コンパイラでは終わりません。この IDE では `[EJ001]` のエラーで止まります。

```emojicode panic
🏁 🍇
  🔂 part 🔫 🔤abc🔤 🔤🔤❗️ 🍇
    😀 part❗️
  🍉
🍉
```

```output この IDE の実行結果
🤯 Program panicked: [EJ001] 🔫 was called with an empty separator. With the official compiler, this never ends.
```

```official
（終わらない）
```

空の文字列は、どの位置にも「見つかる」ので、区切ったあとに次を探す位置が進まないためです。

避けるには、区切りが空でないことを確かめてから `🔫` を呼びます。1 文字ずつに分けたいときは、`🔂` で文字列を回します（[文字列](../basics/strings.md)）。

```keywords
split
分割
空文字列
無限ループ
```

## リストの `🐼` を空のリストに使うと、リストの外を読む {#EJ002}

`🐼`（最後の要素を取り出す）を空のリストに使うと、公式コンパイラでは、リストの長さが -1 になり、リストの外のメモリを読みます。標準ライブラリのドキュメントコメントには「空なら値なしを返す」と書かれていますが、そうなりません。

```emojicode
🏁 🍇
  🆕🍨🐚🔢🍆❗️ ➡️ 🖍🆕 list
  ↪️ 🐼 list❗️ ➡️ last 🍇
    😀 🔤取り出した🔤❗️
  🍉
  😀 🔡 📏 list❓❗️❗️
🍉
```

```output
-1
```

公式コンパイラの `🐼` は、空かどうかを確かめずに長さを 1 減らし、その位置（-1 番目）の値を返します。

避けるには、`🐼` の前に `📏` で空でないことを確かめます（[リストと辞書](../basics/collections.md)）。

```keywords
🐼
pop
空のリスト
```

`🧠`（メモリ領域）の `🐽` で取り出したクラスのインスタンス（文字列など）に、変数に入れずにそのままメソッドを呼ぶと、公式コンパイラは正しくないコードを作って落ちます。この IDE では `[EJ004]` のコンパイルエラーになります。

親の型引数に自分の型引数を渡しているクラス（下の `🧺` は `🎁` に `A` を渡している）に `🔲` でキャストすると、公式コンパイラは落ちるか、終わらなくなります。型を値として使うところ（型のメソッドの呼び出しなど）でも同じです。この IDE では `[EJ005]` のコンパイルエラーになります。

## いちばん小さい整数を `🔡` で文字列にすると、関係のないメモリを読む {#EJ007}

`🔢` のいちばん小さい値（-9223372036854775808）を `🔡` で文字列にすると、公式コンパイラでは、NUL 文字が並んだあとに、関係のない文字が出ます。どの文字になるかは環境によって違います。

```emojicode norun
🏁 🍇
  -9223372036854775807 ➖ 1 ➡️ smallest
  😀 🔡 smallest❗️❗️
🍉
```

```official
（NUL 文字 18 個のあとに - と、関係のない 1 バイト。この IDE では -8）
```

数字を作る前に符号を取るのですが、いちばん小さい値の符号を反転すると、`🔢` の範囲を超えて負のままになります。負の値で数字の表を引くので、表の外を読みます。

避けるには、いちばん小さい値になりうるときは `🔡` の前に確かめて、その値だけは文字列で書きます。

```keywords
整数
最小値
INT64_MIN
LLONG_MIN
文字列に変換
to_string
```

## 無限大や NaN、大きすぎる実数を `🔡` で文字列にすると壊れる {#EJ008}

整数の部分が `🔢` に収まらない実数（無限大、NaN、9223372036854775808.0 以上など）を `🔡` で文字列にすると、公式コンパイラは C++ で未定義動作になる変換をします。結果は CPU によって違い、数字の表の外を読むこともあります。

```emojicode
🏁 🍇
  1.0 ➗ 0.0 ➡️ infinity
  😀 🔡 infinity❗️❗️
🍉
```

```output
9223372036854775807.000000
```

公式コンパイラは、実数を文字列にするとき、整数の部分を C++ の `long long` に変換してから数字にします。`long long` に収まらない値の変換は未定義動作です。公式コンパイラでは収まる範囲の端の値になりますが、`-∞` では符号を取った値が負のままになり、数字の表の外を読みます（[文字列](../basics/strings.md)）。

避けるには、`🔡` の前に、値が範囲に入っているかを確かめます。NaN は [NaN の比較のバグ](#EJ017) で見分けにくいので、0 で割らないなど、計算のほうで避けます。

```keywords
実数を文字列に
無限大
infinity
inf
NaN
long long
```

## `📦 json` で、入力が小数点や `e` で終わると、入力の外を読む {#EJ010}

`json` パッケージで、`1.` や `1e` のように、小数点や `e`（`E`）で終わる入力を読むと、公式コンパイラは、入力の終わりの次のバイトを読みます。そこはふつう数字ではないので、`1.` は `Expected digit after decimal point` のエラーになり、`1e` は 1.0 になります。この IDE では、入力の外は読まずに、同じ結果にしています。

```emojicode
📦 json 🏠

🏁 🍇
  🔂 text 🍿 🔤1.🔤 🔤1e🔤 🍆 🍇
    🆗 value ⚪️🕊🌸 text❗️ 🍇
      ↪️ 🔲 value 💯 ➡️ r 🍇
        😀 🔤🧲text🧲 → 🧲🔡 r 1❗️🧲🔤❗️
      🍉
    🍉
    🙅 error 🍇
      😀 🔤🧲text🧲 → 🧲💬 error❗️🧲🔤❗️
    🍉
  🍉
🍉
```

```output
1. → Expected digit after decimal point
1e → 1.0
```

`json` は、入力のバイトを範囲を確かめない読み方（`🧠` の `🐽`）で読んでいて、小数点や `e` の次の文字を、入力が終わっているかを確かめずに読みます（[パッケージとドキュメントコメント](../advanced/packages.md)）。

避けるには、読む前に、入力の最後の文字が `.` や `e` `E` でないことを確かめます。

```keywords

小数点
```

## 実数を文字列にすると、四捨五入されずに切り捨てられる {#EJ011}

`🔡 実数 桁数❗️` は、指定した桁より下を切り捨てます。さらに、実数の誤差のせいで、思ったより 1 小さい値になることがあります。

```emojicode
🏁 🍇
  😀 🔡 3.05 2❗️❗️
  😀 🔡 3.14159❗️❗️
🍉
```

```output
3.04
3.141589
```

正しくは `3.05`、`3.141590` です。桁数を省いた `🔡 実数❗️` は小数点以下 6 桁なので、同じことが起きます。

```emojicode
🏁 🍇

  😀 🔡 3.14159 ➕ 0.0000005❗️❗️
🍉
```

```output
3.05
3.141590
```

## 文字列の `↔️` が、-1・0・1 を返すとは限らない {#EJ014}

文字列の `↔️`（順番を比べる）は、標準ライブラリのドキュメントコメントでは -1・0・1 を返すメソッドですが、バイト数が同じときは、C の `memcmp` が返した数をそのまま返します。

```emojicode
🏁 🍇
  😀 🔡 ↔️ 🔤abc🔤 🔤abz🔤❗️❗️❗️
  😀 🔡 ↔️ 🔤abz🔤 🔤abc🔤❗️❗️❗️
  😀 🔡 ↔️ 🔤abc🔤 🔤abc🔤❗️❗️❗️
🍉
```

```output
-23
23
```

## `📦 files` の `📤` `📥` `📯` が使えない {#EJ029}

`files` パッケージのソース（`files.🍇`）には、標準出力・標準入力・標準エラーを表す `📤` `📥` `📯` が書かれていますが、コメントになっていて宣言されておらず、C++ 側の中身もありません。使うと `has no suitable 📤` のようなコンパイルエラーになります。

避けるには、標準出力には `😀`、標準入力には `👂🏼` を使います（[標準入力](../basics/input.md)）。

```keywords
files
stdout
stdin
stderr
has no suitable
```

## `🔐` が、ミューテックスをロックできたかどうかを返さない {#EJ030}

`🔐`（ミューテックスをロックできるか試す）は `👌` を返すメソッドとして宣言されていますが、中身の C++ の関数は、ロックを試したあと何も返していません。公式コンパイラでは、ロックを試した結果がそのまま戻り値になりますが、保証はありません。この IDE にはスレッドがないので、`🔐` はいつも `👍` を返します（[システムとスレッド](../advanced/system.md)）。

```emojicode
🏁 🍇
  🆕🔐❗️ ➡️ lock
  ↪️ 🔐 lock❗️ 🍇
    😀 🔤ロックできた🔤❗️
    🔓 lock❗️
  🍉
🍉
```

```output
ロックできた
```

避けるには、`🔐` の結果に頼らず、`🔒` でロックします。

```keywords
mutex
try_lock
ミューテックス
ロック
排他制御
```

## `🔲` でキャストした値を変数に入れると、片付けるときに解放したメモリを読む {#EJ031}

変数に入っているクラスのインスタンス（文字列など）やリストを `🔲` でキャストして、`➡️` で別の変数に入れると、公式コンパイラでは、片付けるときに同じものを 2 回解放しようとして、解放したメモリを読みます。落ちることも、何も起きずに終わることもあります。

```emojicode
📦 json 🏠

🏁 🍇
  🍺 ⚪️🕊🌸 🔤"abc"🔤❗️ ➡️ value
  ↪️ 🔲 value 🔡 ➡️ text 🍇
    😀 text❗️
  🍉
🍉
```

```output
abc
```

公式コンパイラは、キャストした結果を入れた変数の分の参照を数えずに、ブロックの終わりで数を減らします。もとの変数の分と合わせて 2 回減らすので、1 回目でオブジェクトが解放され、2 回目は解放したメモリを読みます（[型の値とキャスト](../types/casting.md)）。

避けるには、キャストする値を変数に入れずに、式のまま `🔲` に渡します。

```emojicode
📦 json 🏠

🏁 🍇
  ↪️ 🔲 🍺 ⚪️🕊🌸 🔤"abc"🔤❗️ 🔡 ➡️ text 🍇
    😀 text❗️
  🍉
🍉
```

```output
abc
```


## 公式コンパイラが内部のチェックで止まる書き方がある {#EJ032}

公式コンパイラは、内部のチェック（C++ の `assert`）を有効にして配布されています。次の書き方では、そのチェックに引っかかって、コンパイルの途中で止まります。この IDE でも `[EJ032]` のエラーで止まります。

- 引数の型を `⚪️` にしたメソッドを書く（呼ばなくても止まります）
- 子クラスで `🔑` の初期化子を書く（[クラスの応用](../advanced/classes.md)）
- `⚪️` を値に持つ辞書（JSON のオブジェクトなど、`🍯🐚⚪️🍆`）から `🐽` で値を取り出す（[パッケージとドキュメントコメント](../advanced/packages.md)）

```emojicode error
🐇 🔎 🍇
  🐇❗️ 📄 a ⚪️ 🍇
    😀 🔤なんでも🔤❗️
  🍉
🍉

🏁 🍇
  📄🐇🔎 1❗️
🍉
```

```text
[EJ032]
```

```official
（コンパイラが Assertion failed: … function typeDefinition で止まる）
```

エラーのメッセージには、どのチェックに引っかかったかが出ます。上の例では、`Type.cpp` の `typeDefinition` のチェックです。

避けるには、引数の型を `⚪️` にする代わりに、メソッドだけのジェネリクスを使います（[クラスの応用](../advanced/classes.md#メソッドだけのジェネリクス)）。子クラスでは `🔑` の初期化子を書かずに、親の初期化子で作ります。JSON のオブジェクトから値を取り出す方法は、公式コンパイラにはありません。

```emojicode
🐇 🔎 🍇
  🐇❗️ 📄 🐚T ⚪️🍆 a T 🍇
    😀 🔤なんでも🔤❗️
  🍉
🍉

🏁 🍇
  📄🐇🔎 1❗️
  📄🐇🔎 🔤x🔤❗️
🍉
```

```output
なんでも
なんでも
```
