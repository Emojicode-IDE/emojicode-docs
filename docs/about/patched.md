# 修正済みのバグ

Emojicode の公式コンパイラ（[`master`](https://github.com/emojicode/emojicode/tree/master)、コミット [`4dec45b`](https://github.com/emojicode/emojicode/commit/4dec45b497e4f4dce7f5f5ae11a00d8e8e9af67c)）にあるバグのうち、この IDE では修正パッチが当たっていて、正しく動くものです。公式コンパイラで同じコードを動かすと、結果が違うことがあります。

修正されていないバグは [Emojicode言語のバグ](known-issues.md) にあります。修正パッチの全体は [emojicode-wasm32.patch](/docs/patches/emojicode-wasm32.patch.txt) で見られます。

## `🔧` で、文字列の最後の日本語や絵文字が壊れる

公式コンパイラでは、`🔧`（前後の空白を取り除く）で、文字列の最後の文字が日本語や絵文字だと、その文字が壊れます。どの環境でも起きます。

```emojicode
🏁 🍇
  😀 🔧 🔤  まわりの空白  🔤❗️❗️
🍉
```

```output この IDE の実行結果
まわりの空白
```

```official
まわりの空�
```

公式コンパイラでは、最後の文字が壊れて `まわりの空�` になります。最後の文字の位置を「その文字の先頭のバイト」として数えているので、2 バイト目より後ろが切り捨てられるためです。修正パッチでは、最後の文字の終わりまでを残します。

```patch s/String.cpp sStringTrim
```

```keywords
trim
空白を除く
文字化け
マルチバイト
UTF-8
```

## `🤷‍♀️` と比べる式で、コンパイラが落ちることがある

公式コンパイラでは、`値 🙌 🤷‍♀️`（値なしとの比較）を含む式をコンパイルするとき、コンパイラの中で、使わない値を作ろうとして未定義動作が起きます。普通のパソコン（x86-64）ではたまたま問題が出ませんが、WebAssembly ではコンパイラが落ちます。

```emojicode
🏁 🍇
  🖍🆕 thing ⚪️
  🔤abc🔤 ➡️ 🖍thing
  ↪️ 🔲 thing 🔢 🙌 🤷‍♀️ 🍇
    😀 🔤数ではない🔤❗️
  🍉
🍉
```

```output この IDE の実行結果
数ではない
```

```official
（コンパイルが終わらない）
```

`🔲 thing 🔢`（`⚪️` を `🔢` にキャストした結果。キャストできなければ値なし）を `🤷‍♀️` と比べています。公式コンパイラをパッチなしで WebAssembly にすると、この例のコンパイルが終わらなくなります（普通のパソコンで動く公式コンパイラでは、たまたま問題が出ないことがあります）。

修正パッチでは、`🤷‍♀️` の側の値を作りません（そもそも必要ないため）。

```patch Compiler/AST/ASTBinaryOperator_CG.cpp
```

```keywords
値なし
nullopt
比較
コンパイラが落ちる
クラッシュ
```

## `📦 files` で、ファイルへの書き込みに失敗してもエラーにならない

公式コンパイラでは、`files` パッケージの `✏️`（ファイルに書き込む）は、エラーを投げることがあるメソッドとして宣言されていますが、中身（C++）がエラーを受け取る引数を持っていません。そのため、書き込みに失敗してもエラーになりません。WebAssembly では、引数の数が合わないとその場で止まるので、書き込み自体ができません。修正パッチでは、引数を足して、書き込みに失敗したらエラーを投げます。

```patch files/File.cpp
```

```keywords
files
ファイル
書き込み
write
```

## クラスの情報の並び方が、コンパイラとランタイムで違う

公式コンパイラでは、クラスのインスタンスが持っている「クラスの情報」の先頭の部分の並び方が、コンパイラ（それを作る側）とランタイム（それを読む側）で食い違っています。64 ビットの環境ではたまたま大きさが同じなので問題になりませんが、32 ビットの WebAssembly ではずれてしまい、インスタンスを片付けるときに落ちます。修正パッチでは、ランタイム側の並び方をコンパイラに合わせます。

```patch runtime/Runtime.h
```

```keywords
クラス
デストラクタ
クラッシュ
32ビット
```

## `🍱` 型の変数を片付けるときに止まる

公式コンパイラでは、複数のプロトコルをまとめた型（`🍱プロトコル プロトコル🍱`、[型の値とキャスト](../types/casting.md)）の **変数** にクラスのインスタンスを入れると、その変数を片付けるところで、関係のない場所を関数として呼んでしまいます。

```emojicode
🐊 🔊 🍇
  ❗️ 🗣 ➡️ 🔡
🍉

🐊 🏃 🍇
  ❗️ 🦵 ➡️ 🔡
🍉

🐇 🐕 🍇
  🐊 🔊
  🐊 🏃
  🆕 🍇🍉
  ❗️ 🗣 ➡️ 🔡 🍇
    ↩️ 🔤ワン🔤
  🍉
  ❗️ 🦵 ➡️ 🔡 🍇
    ↩️ 🔤タタタ🔤
  🍉
🍉

🏁 🍇
  🖍🆕 pet 🍱🔊🏃🍱
  🆕🐕❗️ ➡️ 🖍pet
  😀 🗣 pet❗️❗️
  😀 🦵 pet❗️❗️
🍉
```

```output この IDE の実行結果
ワン
タタタ
```

```official
ワン
タタタ
（最後に null function or function signature mismatch で止まる）
```

`🍱` の値を入れた箱の先頭には、「箱の情報」ではなく「プロトコルごとの対応表の一覧」が入っています。公式コンパイラは、片付けるときだけそれを「箱の情報」として読むので、一覧の外を読んで、そこにある値を関数として呼んでしまいます（上の結果は、パッチなしで WebAssembly にした場合です）。修正パッチでは、一覧の最初の対応表から、片付ける関数を取り出します。

```patch Compiler/Generation/FunctionCodeGenerator.cpp
```

```keywords
🍱
multiprotocol
複数のプロトコル
signature mismatch
```

## WebAssembly で動かすための変更

バグではありませんが、ブラウザの中で動かすために、公式コンパイラから変えているところです。

### 32 ビットの環境に合わせる

公式コンパイラは、メモリを確保する `malloc` に 64 ビットの大きさを渡します。32 ビットの WebAssembly では型が合わないので、間に 1 つ関数をはさんでいます。

```patch Compiler/Generation/RunTimeHelper.cpp
```

```patch runtime/main.cpp
```

クロージャを C++ に渡すときの形も、公式コンパイラは x86-64 の決まりに頼っています。WebAssembly のときだけ、受け取り方を変えています。

```patch s/String.cpp sStringCodepoints
```

### プロセスを起動しない

コンパイラはリンクのために外部のコマンドを起動しますが、ブラウザの中ではできません。リンクは別に用意した WebAssembly のリンカーで行い、`💻`（コマンドの実行）も何もしないようにしています。

```patch Compiler/Compiler.cpp
```

```patch s/System.cpp
```

### スレッドなし

ブラウザの中ではスレッドを使わないので、`🧵` は渡したクロージャをその場で実行するだけにしています（[Thread_wasi.cpp](/docs/patches/Thread_wasi.cpp.txt)）。

### コンパイラそのものを WebAssembly にする

Emojicode のコンパイラは LLVM 8 を使っています。LLVM 8 を WebAssembly 向けにビルドするための変更は [llvm-8.0.1-wasi.patch](/docs/patches/llvm-8.0.1-wasi.patch.txt) にあります。
