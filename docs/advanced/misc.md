# 細かい記法

ふだんはあまり使わない、上級者向けの記法です。

## 値を返さない（◼️）

戻り値の型の位置に `◼️` を書くと、「値を返さない」ことをはっきり書けます。クロージャの型で使うことが多いです。

```emojicode
🏁 🍇
  🍇 ➡️ ◼️
    😀 🔤何も返さない🔤❗️
  🍉 ➡️ f
  ⁉️ f❗️
🍉
```

```output
何も返さない
```

```keywords
void
戻り値なし
◼
```

## 型の大きさ（⚖️）

`⚖️型` は、その型の値 1 つが何バイトかを返します。

```emojicode
🏁 🍇
  😀 🔡 ⚖️🔢❗️❗️
  😀 🔡 ⚖️💯❗️❗️
  😀 🔡 ⚖️👌❗️❗️
🍉
```

```output
8
8
1
```

```keywords
sizeof
大きさ
バイト数
⚖
```

## 非推奨（⚠️）

メソッドに `⚠️` をつけると、そのメソッドを使ったところで警告が出ます。動きは変わりません。

```emojicode
🐇 🧓 🍇
  ⚠️🐇❗️ 📠 🍇
    😀 🔤古いメソッド🔤❗️
  🍉
🍉

🏁 🍇
  📠🐇🧓❗️
🍉
```

```output
古いメソッド
```

コンパイルすると `⚠️ warning: 📠 is deprecated.` という警告が出ます。

```keywords
deprecated
[[deprecated]]
非推奨
警告
⚠
```

## インライン化（🥯）

メソッドに `🥯` をつけると、呼び出すところに中身を展開するようコンパイラに頼みます。動きは変わりません。

```emojicode
🐇 ➰ 🍇
  🥯🐇❗️ ✌️ n 🔢 ➡️ 🔢 🍇
    ↩️ n ✖️ 2
  🍉
🍉

🏁 🍇
  😀 🔡 ✌️🐇➰ 21❗️❗️❗️
🍉
```

```output
42
```

```keywords
inline
インライン
最適化
```

## 安全でない処理（☣️）

`☣️ 🍇 … 🍉` の中では、メモリを直接扱うような、安全でない処理を書けます。標準ライブラリの中で使われていますが、ふつうのプログラムで使うことはありません。

```emojicode
🏁 🍇
  ☣️ 🍇
    😀 🔤unsafe の中🔤❗️
  🍉
🍉
```

```output
unsafe の中
```

メソッドや初期化子の前に `☣️` をつけると、それは「安全でない関数」になります。中では `☣️ 🍇 … 🍉` なしで安全でない処理を書けますが、呼ぶ側は `☣️ 🍇 … 🍉` の中で呼ばなければなりません。下で説明する `🧠` のメソッドや初期化子は、どれも安全でない関数です。

```emojicode
🐇 🧰 🍇
  🆕 🍇🍉
  ☣️❗️ 🔨 ➡️ 🔢 🍇
    🆕🧠 8❗️ ➡️ m
    5 ➡️ 🐽🐚🔢🍆 m 0❗️
    ↩️ 🐽🐚🔢🍆 m 0❗️
  🍉
🍉

🏁 🍇
  🆕🧰❗️ ➡️ t
  ☣️ 🍇
    😀 🔡 🔨 t❗️❗️❗️
  🍉
🍉
```

```output
5
```

`☣️ 🍇 … 🍉` の外で呼ぶと、コンパイルエラーになります。

```emojicode error
🏁 🍇
  🆕🧠 8❗️ ➡️ m
🍉
```

```text
requires ☣️  block.
```

```keywords
unsafe
安全でない
☣
```

### メモリ領域（🧠）

`🧠` は、確保したメモリ領域の場所を表す値型です。中は型のないバイトの並びで、先頭から何バイト目かを指定して、好きな型の値を読み書きします。どの位置に何の型の値を置いたかは、自分で覚えておかなければなりません。範囲の外を読み書きしても、型を間違えて読んでも、エラーにはならず、未定義動作になります。

| 書き方 | 意味 |
|---|---|
| `🆕🧠 バイト数❗️` | その大きさの領域を確保する。中身は決まっていない（0 とは限らない） |
| `値 ➡️ 🐽🐚型🍆 メモリ 位置❗️` | 先頭から「位置」バイト目に、その型の値を書き込む |
| `🐽🐚型🍆 メモリ 位置❗️` | 「位置」バイト目にある、その型の値を読む |
| `♻️🐚型🍆 メモリ 位置❗️` | 「位置」バイト目に置いた値を手放す |
| `🏗 メモリ バイト数❗️` | 領域の大きさを変える。前の中身は残る |
| `🚜 メモリ 書く位置 元のメモリ 読む位置 バイト数❗️` | 元のメモリの「読む位置」から「バイト数」だけ、こちらの「書く位置」にコピーする |
| `✍️ メモリ 💧値❗️ 位置 バイト数❗️` | 「位置」から「バイト数」だけを、その 1 バイトの値で埋める |
| `↔️ メモリ ほかのメモリ バイト数❗️` | 先頭から「バイト数」だけを比べる。同じなら 0 |

`⚖️🔢` は 8 なので、整数を並べるときは 0、8、16 … バイト目に置きます。`🏗` は領域を置き直すことがあり、そのときは場所を表す値が書き換わるので、変数は `🖍🆕` で作っておきます。`🚜` は、元と書き込み先が同じ領域でも、コピーする範囲が重なっていてもかまいません（C の `memmove`）。

```emojicode
🏁 🍇
  ☣️ 🍇
    🆕🧠 16❗️ ➡️ 🖍🆕 m
    10 ➡️ 🐽🐚🔢🍆 m 0❗️
    20 ➡️ 🐽🐚🔢🍆 m 8❗️
    😀 🔡 🐽🐚🔢🍆 m 8❗️❗️❗️
    🏗 m 32❗️
    🚜 m 16 m 0 16❗️
    😀 🔤🧲🔡 🐽🐚🔢🍆 m 16❗️❗️🧲 🧲🔡 🐽🐚🔢🍆 m 24❗️❗️🧲🔤❗️
    ✍️ m 💧0❗️ 0 8❗️
    😀 🔡 🐽🐚🔢🍆 m 0❗️❗️❗️
  🍉
🍉
```

```output
20
10 20
0
```

`↔️` は C の `memcmp` と同じで、最初に違うバイトが、こちらのほうが小さければ負の数、大きければ正の数を返します。0 でないときの値そのものには意味がないので、符号だけを見ます。

```emojicode
🏁 🍇
  ☣️ 🍇
    🆕🧠 4❗️ ➡️ a
    🆕🧠 4❗️ ➡️ b
    ✍️ a 💧1❗️ 0 4❗️
    ✍️ b 💧1❗️ 0 4❗️
    ↪️ ↔️ a b 4❗️ 🙌 0 🍇
      😀 🔤同じ🔤❗️
    🍉
    ✍️ b 💧2❗️ 3 1❗️
    ↪️ ↔️ a b 4❗️ ◀️ 0 🍇
      😀 🔤a のほうが小さい🔤❗️
    🍉
  🍉
🍉
```

```output
同じ
a のほうが小さい
```

`🧠` の値は、領域そのものではなく場所を表します。別の変数に入れても、同じ領域を指す値がもう 1 つできるだけで、中身はコピーされません。領域は、それを指す `🧠` がなくなった時点で片付けられます。`🏗` で場所が変わると、ほかの変数に入れておいた古い場所は使えなくなることがあるので、`🏗` は、その領域を指す `🧠` が 1 つだけのときに使います。

```emojicode
🏁 🍇
  ☣️ 🍇
    🆕🧠 8❗️ ➡️ a
    a ➡️ b
    42 ➡️ 🐽🐚🔢🍆 b 0❗️
    😀 🔡 🐽🐚🔢🍆 a 0❗️❗️❗️
  🍉
🍉
```

```output
42
```

文字列やクラスのインスタンスのような、参照の数を数えている値（[メモリと参照](memory.md)）を置くときは注意がいります。`🐽` で書き込むと参照が 1 つ増えますが、領域が片付けられても中の値は手放されません。置いた値がいらなくなったら、上書きする前や領域を捨てる前に、`♻️🐚型🍆` で 1 つずつ手放します。同じ理由で、こうした値を `🚜` でバイトとしてコピーしてはいけません。1 つずつ `🐽` で読んで書き込みます。

```emojicode
🏁 🍇
  ☣️ 🍇
    🆕🧠 ⚖️🔡❗️ ➡️ m
    🔤りんご🔤 ➡️ 🐽🐚🔡🍆 m 0❗️
    🐽🐚🔡🍆 m 0❗️ ➡️ s
    😀 s❗️
    ♻️🐚🔡🍆 m 0❗️
  🍉
🍉
```

```output
りんご
```

### 文字列とバイト列の中身（🧠）

`🔡`、`📇`、`🔠` は、中身を `🧠` に持っています。`🧠 値❗️` で、その `🧠` をコピーせずに取り出せます。`🔡` と `📇` では UTF-8 のバイトが先頭から並び、`🔠` では今まで足した分が並びます。何バイトあるかは `📐 文字列❗️`、`📏 バイト列❓`、`📐 ビルダー❗️` でわかります。

反対に、`🧠` の先頭から決まったバイト数をコピーして、`🔡` や `📇` を作ることもできます。バイトが UTF-8 として正しいかは調べません。

| 書き方 | 意味 |
|---|---|
| `🧠 文字列❗️` | `🔡` の中身の `🧠` |
| `🧠 バイト列❗️` | `📇` の中身の `🧠` |
| `🧠 ビルダー❗️` | `🔠` の中身の `🧠` |
| `🆕🔡 メモリ バイト数❗️` | 先頭から「バイト数」だけをコピーして、文字列を作る |
| `🆕📇 メモリ バイト数❗️` | 先頭から「バイト数」だけをコピーして、バイト列を作る |

`🔡` と `📇` は変わらない値なので、`🧠` で取り出した領域は読むだけにします。書き込んだときの動きは決まっていません（標準ライブラリのソースのコメントにそう書かれています）。

```emojicode
🏁 🍇
  ☣️ 🍇
    🔤Hi!🔤 ➡️ s
    🧠 s❗️ ➡️ m
    🔂 i 🆕⏩ 0 📐 s❗️❗️ 🍇
      😀 🔡 🐽🐚💧🍆 m i❗️❗️❗️
    🍉
    😀 🆕🔡 m 2❗️❗️

    🆕🧠 3❗️ ➡️ w
    💧65❗️ ➡️ 🐽🐚💧🍆 w 0❗️
    ✍️ w 💧66❗️ 1 2❗️
    😀 🆕🔡 w 3❗️❗️
  🍉
🍉
```

```output
72
105
33
Hi
ABB
```

### リテラルからリストや辞書を作る（🍪）

`🍿 … 🍆` や `🍯 … 🍆` のリテラルを書くと、コンパイラは値をメモリに並べて、`🍨` や `🍯` の初期化子 `🍪` を呼ぶコードにします。`🍪` は安全でない初期化子で、自分で呼ぶこともできます。

| 書き方 | 意味 |
|---|---|
| `🆕🍨🐚要素の型🍆 ▶️🍪 値のメモリ 個数❗️` | メモリに並んだ値を、その個数だけ入れたリストを作る |
| `🆕🍯🐚値の型🍆 ▶️🍪 キーのメモリ 値のメモリ 個数❗️` | 同じ位置にあるキーと値の組を、その個数だけ入れた辞書を作る |

値のメモリには、要素を `⚪️` として、`⚖️⚪️` バイトおきに並べます。要素の型の大きさおきではありません。リストや辞書の中では、要素がどの型の値でも `⚪️` と同じ形で扱われているからです。辞書のキーは `🔡` のまま、`⚖️🔡` バイトおきに並べます。`⚖️⚪️` の値は環境によって違うので、数を直接書かずに `⚖️` で求めます。

値はリストや辞書にコピーされるので、並べるのに使ったメモリの中の値は、作ったあとで `♻️` で手放します。

```emojicode
🏁 🍇
  ☣️ 🍇
    ⚖️⚪️ ➡️ v
    🆕🧠 3 ✖️ v❗️ ➡️ values
    10 ➡️ 🐽🐚⚪️🍆 values 0❗️
    20 ➡️ 🐽🐚⚪️🍆 values v❗️
    30 ➡️ 🐽🐚⚪️🍆 values 2 ✖️ v❗️
    🆕🍨🐚🔢🍆 ▶️🍪 values 3❗️ ➡️ list
    🔂 i 🆕⏩ 0 3❗️ 🍇
      ♻️🐚⚪️🍆 values i ✖️ v❗️
    🍉
    🔂 x list 🍇
      😀 🔡 x❗️❗️
    🍉

    ⚖️🔡 ➡️ k
    🆕🧠 2 ✖️ k❗️ ➡️ keys
    🆕🧠 2 ✖️ v❗️ ➡️ prices
    🔤りんご🔤 ➡️ 🐽🐚🔡🍆 keys 0❗️
    🔤みかん🔤 ➡️ 🐽🐚🔡🍆 keys k❗️
    100 ➡️ 🐽🐚⚪️🍆 prices 0❗️
    250 ➡️ 🐽🐚⚪️🍆 prices v❗️
    🆕🍯🐚🔢🍆 ▶️🍪 keys prices 2❗️ ➡️ dict
    🔂 i 🆕⏩ 0 2❗️ 🍇
      ♻️🐚🔡🍆 keys i ✖️ k❗️
      ♻️🐚⚪️🍆 prices i ✖️ v❗️
    🍉
    ↪️ 🐽 dict 🔤みかん🔤❗️ ➡️ p 🍇
      😀 🔡 p❗️❗️
    🍉
  🍉
🍉
```

30
250

## ジェネリクスの型ごとの処理を省く（🎍🛢）

ジェネリックな値型に `🎍🛢` をつけると、型引数ごとの実行時の情報を作らないようにします。標準ライブラリのリストや辞書の中で使われています。

```emojicode
🎍🛢 🕊 📦🐚T ⚪️🍆 🍇
  🖍🆕 v T
  🆕 🍼 v T 🍇🍉
  ❗️ 📤 ➡️ T 🍇
    ↩️ v
  🍉
🍉

🏁 🍇
  😀 📤 🆕📦🐚🔡🍆 🔤ok🔤❗️❗️❗️
🍉
```

```output
ok
```

```keywords
🛢
generic dynamism
```
