# 継承

## 親クラスを決める

クラス名の後ろに、もう 1 つクラス名を書くと、そのクラスを **継承** します。親クラスのインスタンス変数とメソッドを、そのまま使えます。

```emojicode
🐇 🐾 🍇
  🖍🆕 name 🔡
  🆕 🍼 name 🔡 🍇🍉

  ❗️ 🗣 🍇
    😀 🔤🧲name🧲 は鳴いた🔤❗️
  🍉

  ❗️ 🚶 🍇
    😀 🔤🧲name🧲 は歩いた🔤❗️
  🍉
🍉

🐇 🐕 🐾 🍇
  ✒️ ❗️ 🗣 🍇
    😀 🔤🧲name🧲: ワン！🔤❗️
  🍉
🍉

🏁 🍇
  🆕🐕 🔤ポチ🔤❗️ ➡️ pochi
  🗣 pochi❗️
  🚶 pochi❗️
🍉
```

```output
ポチ: ワン！
ポチ は歩いた
```

`🐇 🐕 🐾` は「`🐾` を継承した `🐕`」です。`🐕` には `🆕` を書いていないので、親の `🆕` がそのまま使えます。

```keywords
継承
extends
inheritance
親クラス
基底クラス
派生クラス
サブクラス
subclass
```

## 上書きする（✒️）

親と同じメソッドを子で作り直すときは、前に `✒️` をつけます。つけ忘れるとコンパイルエラーになるので、うっかり上書きしてしまうことがありません。

```emojicode error
🐇 🐾 🍇
  🆕 🍇🍉
  ❗️ 🗣 🍇
    😀 🔤…🔤❗️
  🍉
🍉

🐇 🐕 🐾 🍇
  ❗️ 🗣 🍇
    😀 🔤ワン🔤❗️
  🍉
🍉

🏁 🍇
  🗣 🆕🐕❗️❗️
🍉
```

```keywords
override
virtual
オーバーライド
上書き
```

## 上書きするときの決まり

`✒️` をつけたメソッドは、親のメソッドの代わりに、親の型の変数からも呼ばれます。そのため、親のメソッドを呼ぶつもりで書いたコードがそのまま動くように、子のメソッドにはいくつかの決まりがあります。

引数の数と型は、親と同じにします。数や型が違うと、上書きする相手が見つからず、`was declared ✒️ but does not override anything.` というエラーになります。親より狭い型（親が `🐾` なら `🐕`）にしたときだけは相手が見つかりますが、その型の引数では親と同じ値を受け取れないので、やはりエラーです。

```emojicode error
🐇 🐾 🍇
  🆕 🍇🍉
🍉

🐇 🐕 🐾 🍇
🍉

🐇 🏠 🍇
  🆕 🍇🍉
  ❗️ 📥 a 🐾 🍇
    😀 🔤ようこそ🔤❗️
  🍉
🍉

🐇 🏡 🏠 🍇
  ✒️ ❗️ 📥 a 🐕 🍇
    😀 🔤犬だけ🔤❗️
  🍉
🍉

🏁 🍇
  📥 🆕🏡❗️ 🆕🐕❗️❗️
🍉
```

```text
of argument 1 is not compatible
```

`✒️` をつけずに引数の型を変えたときは、どう変えたかで分かれます。親より広い型や関係のない型にしたメソッドは、上書きではなく、同じ名前の別のメソッドになります（[同じ名前で引数の違うメソッド](classes.md)）。親より狭い型にしたメソッドは、上書きの相手が見つかるので、`If you want to override 📥 add ✒️.` というエラーになります。

戻り値の型は、親と同じか、親より狭い型にできます。親が `🐾` を返すなら、子は `🐕` を返してもかまいません。子のインスタンスから呼んだときは、狭いほうの型として使えます。

```emojicode
🐇 🐾 🍇
  🆕 🍇🍉
🍉

🐇 🐕 🐾 🍇
  ❗️ 🦴 🍇
    😀 🔤骨をかじる🔤❗️
  🍉
🍉

🐇 🏠 🍇
  🆕 🍇🍉
  ❗️ 🐣 ➡️ 🐾 🍇
    ↩️ 🆕🐾❗️
  🍉
🍉

🐇 🏡 🏠 🍇
  ✒️ ❗️ 🐣 ➡️ 🐕 🍇
    ↩️ 🆕🐕❗️
  🍉
🍉

🏁 🍇
  🦴 🐣 🆕🏡❗️❗️❗️
🍉
```

```output
骨をかじる
```

`🦴` は `🐕` だけのメソッドですが、`🏡` の `🐣` が `🐕` を返すので呼べます。親の戻り値の型に入らない型（`🐾` に対して `🔢` など）にすると、`is not compatible to the return type defined in` というエラーになります。

見える範囲は、親と同じか、より広くします。親が `❗️`（どこからでも呼べる）なのに子で `🔐❗️` や `🔒❗️` にすると、`Overriding method must be as accessible or more accessible than the overridden method.` というエラーです。子で何もつけなければ、親と同じ見える範囲になります。

最後に、親のメソッドが `👇` や引数をメソッドの外に持ち出さないなら、子のメソッドも持ち出してはいけません。持ち出すとは、インスタンス変数やリストにしまうなどして、メソッドが終わったあとも残るようにすることです。持ち出されない引数に渡す値は、呼ぶ側でスタックに置くなど、軽く扱えるようにコンパイルされるからです。逆に、親が持ち出すメソッドを、子で持ち出さないように上書きするのはかまいません。

```emojicode error
🐇 📝 🍇
  🖍🆕 items 🍨🐚🔡🍆
  🆕 🍇
    🆕🍨🐚🔡🍆❗️ ➡️ 🖍items
  🍉
  ❗️ 📥 s 🔡 🍇
    😀 s❗️
  🍉
🍉

🐇 🗂 📝 🍇
  ✒️ ❗️ 📥 s 🔡 🍇
    🐻 items s❗️
  🍉
🍉

🏁 🍇
  📥 🆕🗂❗️ 🔤メモ🔤❗️
🍉
```

```text
Function lets parameter "s" escape
```

`👇` を持ち出したときは `Function lets this context escape` になります。親のメソッドに `🔏` がついていると、そもそも上書きできません（[クラスの応用](../advanced/classes.md)）。

```keywords
override
オーバーライドの規則
共変戻り値
covariant return type
リスコフの置換原則
does not override anything
not compatible to the return type
as accessible or more accessible
escape
エスケープ
持ち出す
```

## 親のメソッドを呼ぶ（⤴️）

上書きしたメソッドの中から親のメソッドを呼ぶときは、`⤴️` を使います。

```emojicode
🐇 🐾 🍇
  🆕 🍇🍉
  ❗️ 🗣 🍇
    😀 🔤（鳴き声）🔤❗️
  🍉
🍉

🐇 🐕 🐾 🍇
  ✒️ ❗️ 🗣 🍇
    ⤴️🗣❗️
    😀 🔤ワン！🔤❗️
  🍉
🍉

🏁 🍇
  🗣 🆕🐕❗️❗️
🍉
```

```output
（鳴き声）
ワン！
```

子クラスで初期化子を作るときは、その中で `⤴️🆕 …❗️` と書いて、親の初期化子を呼びます。

```emojicode
🐇 🐾 🍇
  🖍🆕 name 🔡
  🆕 🍼 name 🔡 🍇🍉
  ❗️ 🏷 ➡️ 🔡 🍇
    ↩️ name
  🍉
🍉

🐇 🐈 🐾 🍇
  🖍🆕 lives 🔢
  🆕 name 🔡 🍇
    9 ➡️ 🖍lives
    ⤴️🆕 name❗️
  🍉
  ❗️ 📋 🍇
    😀 🔤🧲🏷👇❗️🧲 は命が 🧲🔡 lives❗️🧲 つ🔤❗️
  🍉
🍉

🏁 🍇
  📋 🆕🐈 🔤タマ🔤❗️❗️
🍉
```

```output
タマ は命が 9 つ
```

子クラスのインスタンス変数に値を入れてから、親の初期化子を呼びます。

```keywords
super
親のメソッド
基底クラスの呼び出し
```

## 親の型として扱う

子クラスのインスタンスは、親クラスの型の変数やリストに入れられます。メソッドを呼ぶと、それぞれの子クラスのメソッドが実行されます。

```emojicode
🐇 🐾 🍇
  🆕 🍇🍉
  ❗️ 🗣 ➡️ 🔡 🍇
    ↩️ 🔤…🔤
  🍉
🍉

🐇 🐕 🐾 🍇
  ✒️ ❗️ 🗣 ➡️ 🔡 🍇
    ↩️ 🔤ワン🔤
  🍉
🍉

🐇 🐈 🐾 🍇
  ✒️ ❗️ 🗣 ➡️ 🔡 🍇
    ↩️ 🔤ニャー🔤
  🍉
🍉

🏁 🍇
  🆕🍨🐚🐾🍆❗️ ➡️ 🖍🆕 animals
  🐻 animals 🆕🐕❗️❗️
  🐻 animals 🆕🐈❗️❗️
  🔂 a animals 🍇
    😀 🗣 a❗️❗️
  🍉
🍉
```

```output
ワン
ニャー
```
